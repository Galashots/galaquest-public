# Unity throughput: persisted material upgrade state

Engineering checkpoint for Issue #155. Base: `77f4c505ecfeac4160c5bc165c34ba63517a976d`.
No Unity/package upgrade, gameplay change, or candidate promotion.

## Causal finding

The base commits `m_LastMaterialVersion: 9` in URP project settings, while all checked-in materials
carrying a URP AssetVersion are already at version 10. The pinned URP 17.3.0 package registers ten
upgraders in `MaterialPostprocessor.k_Upgraders`.
Read-only reflection against the loaded pinned URP assembly independently returned an upgrader count of 10.

Its `MaterialReimporter.RegisterUpgraderReimport` compares the project marker with that count and
reimports all materials when they differ. `MaterialPostprocessor.SaveAssetsToDisk` detects
`-testResults`, updates the marker in memory, and returns without persisting the project settings.
This is one confirmed source of repeat upgrade work when the callback's URP/current-frame conditions
hold; its share of the historical refresh cost is unmeasured. The historical log explicitly reports
the Material Upgrader re-import, but that does not attribute all downstream imports to this marker.

The historical Rune Forge test log reports a 95.644-second refresh: 98 actual imports, 3 cached imports,
zero changed source files, and 94.814 seconds in ImportInProcess. This is historical evidence on a
different checkout, not a controlled before/after measurement of this patch.

## Correction and regression

Retain the completed migration output generated by the installed pinned Editor: material version 10
and its default resource-folder field. The entire settings diff was inspected before transfer from
the existing Editor checkout. No material file was copied or changed. The resource-folder field equals
the pinned package's `UniversalProjectSettings` default; persisting it does not create new assets.
A Node regression checks that
the persisted marker agrees with the checked-in URP-versioned material corpus; it failed on the base
with `9 !== 10`, then passed with the generated settings.

This test catches the observed stale-marker regression. It does not replace running the pinned Editor
or prove that an arbitrary future package upgrade needs no migration.

Import qualification still matters: URP initializes an unversioned non-ShaderGraph material from the
project marker. At 10 it will not run UpgradeV10's emission fixup that a marker of 9 would apply.
All 15 current material files already carry version 10, so this patch changes no current material.
New unversioned material imports must be explicitly qualified/migrated rather than assumed to be
current. The guard requires every committed material to carry a version, pins the expected level to
URP 17.3.0, and rejects lowering both the marker and materials together. A future non-URP material
needs a deliberate documented guard exception instead of silently dropping out of the inventory.

## Remaining Issue #155 work

- Controlled same-checkout import/test timings and final candidate Editor acceptance remain required.
- Preview generation currently creates and deletes its candidate folder on every build; unchanged-input
  reuse is not implemented by this checkpoint.
- Performance Testing 3.0.3 arrives transitively through Collections. Its `TestRunBuilder` implements
  ordinary build callbacks without checking IncludeTestAssemblies, writes Resources metadata, then
  removes it on cleanup. Its separate assembly filter excludes the runtime assembly from ordinary
  builds. The write-if-equal check does not prevent recreate-after-cleanup churn. No package source was
  patched; a supported narrow exclusion still needs investigation.
- Interaction preflight and unchanged/changed-script fast WebGL benchmarks remain unverified.

This checkpoint must not close Issue #155 or claim a 95-second measured speedup.
