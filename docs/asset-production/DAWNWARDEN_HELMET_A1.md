## Step 1 — the reusable decimation script

`tools/blender/decimate_gear.py` is a small reusable reducer for **rigid** gear, modelled on
`tools/blender/decimate_hero.py` (which owns the skinned character case). It imports, collapse-
decimates to the requested budget, and exports. It performs no modelling, no anatomy, no rigging, no
material normalization, and no fit.

What it does and refuses, all printed rather than assumed:

- refuses the source unless the declared glTF is single-mesh / single-primitive / single-material, and
  refuses any input that declares skins or animations — so it cannot silently mangle a rigged
  character (it points at `decimate_hero.py` instead);
- requires a UV layer, and first attempts a **UV-delimited** collapse so it does not tear texture
  islands; only if that cannot reach the budget does it retry unconstrained, and it says so;
- re-reads the exported file from disk and asserts `<= target` triangles, unchanged 1/1/1 shape, and
  the presence of `POSITION` / `NORMAL` / `TEXCOORD_0`;
- never writes to the source file.

Exact command:

```bash
blender --background --factory-startup --python tools/blender/decimate_gear.py -- \
  public/assets/gear/candidates/dawnwarden-helmet-v1.glb \
  unity/GalaQuest/GearSources/dawnwarden-helmet-v1-lod.glb 2000
```

## Step 3 — where the reduced GLB lives, and the asset registry

The reduced GLB is the **source of a Unity derivative**, not a runtime asset, so it lives beside its consumer at
`unity/GalaQuest/GearSources/` (outside `Assets/`, so Unity does not import it) rather than under
`public/assets/`. The FBX provenance record's `sourceRepoPath` points there. (It was first written under
`public/assets/gear/candidates/` before commit; re-converting from the new path produced the same FBX
bytes, sha256 `33a36c61…`.)

Why not `public/assets/gear/candidates/` plus a registry entry: everything under `public/assets` must be
declared in `asset-registry-v1.evidence.json`, and regenerating `asset-registry-v1.json` breaks the Unity
Migration Bridge. `tools/unity-migration/export-bridge.mjs` pins the **whole registry file** to its
originating commit (`28eb619…`), so a registry change forces re-pinning `BridgeManifest.json`,
`Migration/Provenance/asset-provenance.json` and the test fixture (`VisibleArmorManifest.json` pins the hero/gear
modules and fit docs, not the registry, so it is unaffected) — and
`asset-provenance.json` can only be regenerated by re-converting the migration derivatives (including the
rigged keeper) with Blender. That cascade is out of scope for a candidate helmet.

**Follow-up (pipeline friction):** the Bridge should pin only the registry records it actually consumes,
so adding a gear candidate no longer ripples into the migration manifests. Until then, the registry
record for this candidate is deferred; its source-custody fact lives in the provenance record above.

## What was NOT done

Stated explicitly so nothing here is read as more than it is:

- **No fit and no mount.** No socket transform, no `GearItemDefinition` seating, no `GearFitFixture`
  measurement, no `GearAssetFitProfile`, no cavity of any kind. The mesh is not placed on the hero.
- **No A2 cavity preset / profile work.** The asset has neither a `MeasuredFromAssetLocator` cavity nor
  an `AuthoredVirtualCavity`; per [gear.md](../pipeline/gear.md) its correct registration state is
  **`NeedsAuthoring`**, and no fit scale is claimed.
- **No Unity import.** The FBX was not imported into a Unity project, no `.meta`/`.asset` was authored,
  no Workbench run, no Editor render, and no gameplay capture.
- **No visual acceptance.** Silhouette preservation was a constraint on the reducer, not a reviewed
  conclusion. Nobody has judged the reduced helmet at gameplay framing. Per
  [asset-visual-review.md](../review-guides/asset-visual-review.md), decimation bytes still require
  human visual review, and running-game pixels remain final appearance authority. Producer self-review
  has not happened either.
- **No texture change, no material normalization.** Materials were preserved, not repaired.
- **No anatomy tagging / semantic region work.** No `_GQ_REGION` attribute, no coverage declaration.
- **No production promotion.** The candidate stays in `candidates/`; the source GLB is unmodified.

**UNKNOWN stays UNKNOWN.** Whether the 2,000-triangle silhouette still reads as the intended
Dawnwarden helmet, whether the 2048 texture is proportionate at runtime, and whether the asset fits the
hero head cavity are all **UNKNOWN** and are not claimed here.
