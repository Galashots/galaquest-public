## Player outcome

A child reaches one dormant Rune Forge pocket in the existing Emberworks scene, sees a MagmaLord
Helmet worth wanting, completes about two short profile-appropriate learning interactions through
physical rune and hammer choices, releases one durable personal entitlement, explicitly equips it,
and can see and use the improvement. A sibling arriving later retains an independent opportunity and
cannot consume or reset the first child's state.

This is one encounter. It is not an Emberworks campaign, curriculum platform, armor factory,
destination expansion, inventory redesign, authentication replacement, or combat rewrite.

## Durable laws

- Learning progress, task history, entitlement, inventory, and equip state belong to the durable
  profile. Shared spectacle never exposes another learner's answers or consumes their opportunity.
- Stable entitlement `emberworks.rune-forge.magmalord-helmet.v1` is independent of task-pack content
  versions. Repeat clicks, reconnects, duplicate messages, content edits, and same-profile tabs cannot
  create a second grant or first-claim ceremony.
- Ownership and equipment remain distinct. Equipping is an explicit player choice using the existing
  durable equipment ordering law.
- The existing newest-valid same-profile connection wins. A superseded socket cannot answer, claim,
  equip, or restore through late callbacks.
- Wrong answers preserve earned value and permit a safe retry. Assistance is recorded separately from
  independent success. Two answers never become a general mastery claim.
- Stats are resolved from equipped gear and consumed by combat before POWER is derived. A stat printed
  only by UI fails this package.
- Existing profile journals remain compatible; the package does not create another save system or
  claim an anti-cheat boundary beyond the repository's current V0 trust model.
